<bug_diagnosis>
Root cause (verified by reading `app/(app)/recipes/index.tsx`):

1. User types "chicken" → `handleSearchChange` sets `searchQuery` AND calls
   `loadAllForSearch()` which populates `allRecipesCache` with the full (up to
   5000) recipe list.
2. `displayedRecipes` memo (line 241-258) resolves:
   `isSearching && allRecipesCache ? allRecipesCache : publicRecipes`
   → uses the full cache → `smartSearch` filters it → user sees results.
3. User taps a result → `router.push` to `/(app)/recipes/[id]`.
4. User taps Back → screen regains focus → `useFocusEffect` (line 172-180)
   re-runs its callback unconditionally → calls `loadPublicData()`.
5. `loadPublicData` (line 94-116) calls `setAllRecipesCache(null)` on line 99
   AND fetches only page 0 (~20 recipes) into `publicRecipes`.
6. `searchQuery` is untouched (separate `useState`), so the text input still
   shows "chicken". But `displayedRecipes` now falls through to:
   `isSearching && allRecipesCache(=null) ? ... : publicRecipes(page 0)`
   → `smartSearch(page_0_only, "chicken")` → usually `[]`.

The user perceives this as "results vanished while my search stayed."

FIX: In the `useFocusEffect` callback, skip the reload when
`searchQuery.trim().length > 0`. The cache and paginated list from the previous
visit are still valid — nothing invalidated them. Additionally, to be fully
correct, if we DO reload and `isSearching` is true, we should NOT null out
`allRecipesCache` in `loadPublicData` (we'd lose the cache for no reason). The
simplest, safest fix is the first one: make the focus reload a no-op while
searching.

Edge cases to preserve:
- If user clears the search ("" → triggers handleSearchChange with empty text),
  the stale page 0 data is fine (it's what's shown when not searching).
- Pull-to-refresh (`onRefresh`) still works — unchanged.
- Tab switching still triggers a fresh load — unchanged (handleTabSwitch).
- Personal tab focus reload still works (searchQuery is cleared by
  handleTabSwitch, so `searchQuery.trim()` is empty when switching).
</bug_diagnosis>
